# 57 ГРАНЕЙ: правила работы Codex

Этот Flutter-репозиторий содержит demo-приложение `57 ГРАНЕЙ` для iOS и Android.

## Всегда

- Сначала выполнить `git status --short` и сохранить unrelated изменения.
- Работать небольшими связанными flow; не добавлять будущую функциональность без запроса.
- Не выполнять `reset`, `checkout`, `restore`, `clean`, `stash` или commit без прямого указания пользователя.
- Figma — источник визуала. Поведение следует Apple HIG на iOS и Material guidance на Android.
- Сначала использовать локальные specs, reference PNG и overlays из `docs/`; обращаться к Figma MCP только когда локальных данных недостаточно.
- Один раз получить нужный Figma context, записать компактный spec и не запрашивать повторно те же nodes без причины.
- Во время разработки запускать только тесты изменяемого flow. `flutter analyze` и полный `flutter test` запускать после завершения flow или по прямому запросу.
- Не менять production-код, native config или зависимости в документационных задачах.
- Не добавлять secrets. `.mapkit.env` локальный и приватный; не читать и не печатать его содержимое.
- Не делать commit до явного указания пользователя.
- Финальный отчёт должен быть коротким: изменения, проверки, известные ограничения и `git status --short`.

## Перед изменением экрана

1. Открыть только относящиеся к flow строки в [SCREEN_INDEX.md](docs/codex/SCREEN_INDEX.md).
2. Прочитать [PROJECT_CONTEXT.md](docs/codex/PROJECT_CONTEXT.md) и соответствующий локальный spec/reference.
3. Следовать [WORKFLOW.md](docs/codex/WORKFLOW.md).
4. Сверить текущие незавершённые работы в [CURRENT_STATE.md](docs/codex/CURRENT_STATE.md).

Не загружать все документы и изображения проекта в контекст одновременно.
